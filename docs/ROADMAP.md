# Roadmap

## Preserve the proven foundation

The accepted DrivenByMoss integration provides current-semantic composition, a validated raster sink, bounded authenticated latest-frame ingress, one Push USB writer, and ordinary-launch activation with private session discovery.

V5A's generated-frame acceptance demonstrated physical Push control/audio continuity, fallback, shutdown/restart and exact official rollback. [Design](design/ordinary-launch-ingress-activation.md) · [Evidence](../evidence/v5a-ordinary-ingress-activation/README.md).

## Current reset

The accumulated V2–V5B capture experiments are retired from current code and architectural structure. Their historical results remain inspectable, but they are not prerequisites or a reusable product framework.

The maintainer wants a simple FFmpeg-based video/composition layer feeding the proven ingress. That is the requested direction, not a selected acquisition API, validated design or implemented backend. No replacement is built in this cleanup.

## Later possibilities, not active structure

Device-aware screens, localization, Linux portability, and managed-appliance operation remain possible future work. They do not impose a resolver, semantic camera, profile system, workspace manager or source-framework hierarchy on the next implementation.

A future usable release must preserve ordinary Bitwig use, controls/audio, bounded current pixels, intelligible installation and clean recovery. It is not established by compiling a capture library or demonstrating a static frame.
