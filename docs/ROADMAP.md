# Roadmap

This is product orientation; the owning issue and `CURRENT_SLICE.md` control active work.

## Proven foundation

Pushwig has established on physical Push hardware:

- a narrow DrivenByMoss composition seam;
- current-semantic restoration;
- a validated opaque-BGRA raster sink;
- bounded authenticated latest-frame ingress;
- real Bitwig pixels at useful cadence and low CPU/RSS;
- preserved pads, encoders, transport, Push audio, and headphones.

## Current: V5 frame-source bakeoff

Stay on macOS and select a product-usable source/media substrate with a credible Linux path.

The work includes unconventional second-screen, game-streaming, and remote-desktop projects alongside GStreamer, FFmpeg/libav, direct raw-capture libraries, WebRTC desktop capture, OBS/libobs, RustDesk, Sunshine, and Weylus.

V5 must identify actual platform backends, compare materially different Mac paths, and either select a winner or retain a justified no-winner result. It does not implement Linux, Weston/PipeWire, Steam Deck, remote desktop, or Windows.

## After a source winner

1. Resume the first Sampler hybrid device page.
2. Redesign Browser as a results-first semantic experience.
3. Add Sampler waveform/boundary/sliced task views after capability verification.
4. Use Polymer as the first device-overview generalization.
5. Expand proven behavior families to analyzers, graph devices, structures, and note-flow devices.

## Portability

After the common substrate is selected:

- implement and prove its Linux source backend on a general Linux fixture;
- preserve backend-neutral raw-frame and presentation contracts;
- later adapt to Steam Deck/appliance constraints;
- retain attached and managed operating modes as separate products.

## Appliance

A later managed appliance combines a Linux host, battery, boot/recovery, Push over USB, and full Bitwig desktop access from another device. The compositor and remote stack remain unselected.

## Release direction

A first credible release lets another Push 3 + Bitwig user install supported components, activate a supported visual experience, retain normal controls/audio, understand limitations, and recover cleanly when visuals are unavailable.
